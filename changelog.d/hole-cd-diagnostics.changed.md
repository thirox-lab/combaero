- **Hole-Cd diagnostics are one `Cd_*` group with the same keys on every hole element.** `OrificeElement` and every subclass (effusion plate and liner panel, film, slot, impingement row, the effective-area and diameter-Cd connections) report `Cd`, `Cd_correlation`, `Cd_base`, `Cd_in_range`, `Cd_extrapolated_*`, and per term (`Cd_inclination_*`, `Cd_inlet_crossflow_*`, `Cd_supply_drive_*` (#1087), `Cd_exit_crossflow_*`) its model, an `_applied` flag and its state, whether or not the term is on. A term that is off reads model `"none"`, `_applied` 0 and neutral values, so a results table has the same columns on every hole (`combaero.network.hole_cd.HOLE_CD_DIAGNOSTIC_KEYS`; the table and the old-to-new mapping are in `docs/API_PYTHON.md`). No value changes: F, J, solves and every old key's value are bit-identical under the mapping (every stress family, probes for every term, the GUI examples).
  - **Renamed outright (never released):** `Cd_no_exit_crossflow` -> `Cd_base`; `exit_crossflow_rho_u2`, `_k_perp`, `_k_used`, `_k_floor`, `_delta`, `_held`, `_faded`, `_floor_above_fit`, `_in_range` -> `Cd_exit_crossflow_*`; `Cd_crossflow_extrapolated_velocity_ratio`, `_l_d`, `_grazing_velocity` -> `Cd_exit_crossflow_extrapolated_*`.
  - **One name for the hole's own Cd.** `Cd_own` (impingement) and `Cd_no_exit_crossflow` (film, effusion) are both `Cd_base` now: the Cd before any exit-crossflow term (Rowbury's loss, or an impingement row's jet law). `Cd_exit_crossflow_ratio` is `Cd / Cd_base` on both.
  - **The exit-crossflow keys are reported when the term is off** (previously absent): the GUI's result keys and the Probe gain them on every hole element.
